# 1.4.6 인증번호 OCR 수정

## 확인한 문제

기존 코드는 같은 이진화 이미지를 3배와 4배로 확대한 결과를 비교했습니다. OCR 엔진은 이를 다시 같은 입력 높이로 정규화하므로 동일한 오인식을 반복해도 일치 판정을 받을 수 있었습니다. 줄 전체의 평균 점수는 일부 글자의 낮은 확신도를 가릴 수도 있었습니다.

전달받은 실제 화면에서는 앞의 한글 라벨 일부가 인증번호에 섞였고, 넓은 픽셀 글꼴의 끝쪽 Z가 2로 인식되는 현상이 재현됐습니다.

## 바뀐 처리

1. 전체 스크린샷에서 녹색 글자와 청록색 SCRMaps 주소를 찾습니다. 글자 높이에 맞춰 줄을 묶고 실제 큰 공백에서 한글 라벨을 분리합니다.
2. 엄격한 녹색 마스크, 희미한 획을 포함하는 마스크, 녹색 명암을 보존하는 영상으로 각각 읽습니다.
3. 결과가 약하면 명암 영상에 세 가지 가로 비율 보정을 적용합니다. 이는 동일 이미지를 균일 확대해 반복하는 것과 다른 처리입니다.
4. RapidOCR 1.4.4의 글자별 CTC 점수를 유지하고 완성된 번호 후보들을 비교합니다. 강한 반대 결과가 있으면 자동 제출을 보류합니다.
5. 실제 빈 열에서 글자를 나누고 최대 여섯 글자의 겹치는 구간들을 다시 읽어 전체 결과와 비교합니다. 글자가 붙어 경계를 확인하지 못하면 수동 확인으로 넘깁니다.
6. 확인 화면에서 의심 위치를 왼쪽부터 1번으로 표시합니다. 원본 번호 부분을 확대하고 인식 후보를 선택할 수 있습니다. 후보 선택만으로 제출되지는 않습니다.

가장 근거가 강한 완성 문자열을 표시합니다. 글자별 조합을 만들어 사이트에 대입하거나 0/1/I/O 등을 임의로 바꾸지 않습니다. 점수는 OCR 모델의 출력이며 정답 확률을 뜻하지 않습니다.

## 확인한 범위

- 전달받은 실제 화면의 25자리 인증번호와 `/CR2` 주소를 읽었습니다. 원본과 75%·125% 크기에서도 같은 번호/주소를 얻었습니다. 이 화면은 일부 구간의 확신도가 낮아 자동 제출을 보류하고 확인 화면을 표시합니다.
- 합성 녹색/청록색 텍스트 24개를 실제 모델로 검사했습니다. 글꼴·크기 두 종류/네 단계와 세 번호를 사용한 제한된 테스트이며, 전체 게임 글꼴의 정확도 지표로 볼 수 없습니다.
- 두 글자가 낮은 점수인데 평균은 높은 경우, 전처리 결과 충돌, 금지 문자, 부분 구간의 오인식, 한글 라벨 분리, 맵 주소 충돌, 자동 제출 보류, 로그인 재개, 확대 원본/후보 UI 및 종료 동작을 검사했습니다.
- 실제 SCRMaps에 인증번호를 보내거나 계정 로그인을 하지 않았습니다. Windows/Mac 설치 파일을 새로 빌드해 실행한 검증은 남아 있습니다. 이번 환경의 GUI 검사는 Linux Qt의 로컬 테스트 페이지를 사용했습니다.

개인 스크린샷과 실제 인증번호는 공개 소스 및 테스트 이미지에 포함하지 않았습니다. 동봉된 PNG 네 개는 합성 테스트 이미지입니다.

## 기존 오프라인 설치판에 파일 패치 적용

별도로 제공한 `SCRMapsHelper_OCR_Patch_1.4.6.zip`은 첨부 소스와 같은 1.4.5 오프라인 설치 구조용입니다.

1. Helper를 완전히 종료합니다.
2. 설치 폴더를 엽니다. 기본 경로는 `%LOCALAPPDATA%\Programs\SCRMapsHelper`입니다. 그 안에 `app\recognition.py`가 있는지 확인합니다.
3. 기존 `app` 폴더를 별도 위치에 백업합니다.
4. 패치 ZIP의 `app` 폴더를 설치 폴더의 `app`과 합쳐 덮어씁니다. `app\app`처럼 이중 폴더를 만들지 마세요. 다섯 Python 파일을 함께 교체합니다.
5. 재실행해 v1.4.6 표시를 확인하고 같은 사진을 불러옵니다. 애매하다고 표시되면 확대 원본과 비교해 확인 후 제출합니다.

기존 프로그램에 포함된 Python/OCR 런타임을 사용하는 파일 패치입니다. 단일 EXE 묶음판처럼 `app` 폴더가 없는 배포 형태는 전체 소스로 다시 빌드해야 합니다. 이 패치는 설치 등록 정보와 기존 payload-manifest를 갱신하는 정식 Setup 업그레이드는 아닙니다. 파일 패치 후 이전 manifest를 기준으로 한 해시 검증에는 차이가 표시됩니다.

## 새 Setup/DMG 배포

전체 소스 ZIP을 풀어 기존 소스에 반영합니다. core.APP_VERSION, Windows 리소스 및 설치 정보는 1.4.6으로 맞췄습니다. GitHub 빌드 경로를 그대로 사용할 수 있습니다. 버전 태그 예시는 `v1.4.6`입니다. 버전과 무관한 기존 설명의 과거 검증 기록은 유지했습니다.

의존성 버전과 OCR 모델은 그대로입니다. 새 모델 다운로드나 새 OCR 엔진 설치를 추가하지 않았습니다. requirements.txt에 있는 RapidOCR 1.4.4의 API를 사용하므로 임의로 다른 버전으로 바꾸면 재검증해야 합니다.

일반 검사:

```sh
python -m unittest discover -s tests -v
```

실제 OCR 모델 검사는 `SCRMAPS_OCR_TEST=1`, Qt 로컬 통합 검사는 `SCRMAPS_QT_TEST=1`로 활성화합니다. 외부 스크린샷 회귀 검사는 `SCRMAPS_OCR_IMAGE`, `SCRMAPS_OCR_EXPECTED`, 선택적으로 `SCRMAPS_OCR_PROJECT`를 설정합니다. tests/test_browser.py의 구형 브라우저 경로 검사는 개발용 Playwright/Chromium이 별도로 필요하며 기본 앱 런타임에는 추가하지 않았습니다.
