# 1.4.9 묶음으로 표시되는 세이브 코드 읽기

제공된 화면은 세이브 코드를 세 글자씩 나누고 하이픈을 사이에 표시했습니다. 1.4.8의 결과 읽기는 공백만 제거했고, 사이트의 `.hud-code` 영역도 직접 읽지 않아 결과를 놓칠 수 있었습니다. 공개 사이트 CSS에서 `.hud-code`와 `.hud-code-group` 표시 클래스가 확인되었습니다. 로그인한 계정의 DOM 구조를 직접 확인한 것은 아닙니다.

1.4.9는 해당 코드 영역을 읽고 문자 묶음 사이의 공백·하이픈을 제거합니다. 예시 `9G5 - C4B - A5R`는 `9G5C4BA5R`로 앱과 기록에 들어가며 F8도 이 문자열을 입력합니다. ASCII 하이픈, 표시용 대시와 마이너스 기호를 처리합니다. 코드의 문자를 추측하거나 0·1·I·O를 다른 글자로 치환하지 않습니다. 인증번호 `valid_code`의 기존 규칙은 유지됩니다.

구분자 제거 전에 문자열 전체가 코드 문자와 구분자로만 되어 있는지 검사합니다. URL의 `:`나 `/`, `_` 같은 문자를 삭제해 코드처럼 만들지 않습니다. 링크와 메뉴·일반 텍스트를 코드로 받지 않는 기존 범위 제한과, 인증번호·맵 주소 부분을 결과로 받지 않는 검사도 유지합니다.

이전 버전에서 결과를 못 가져온 경우 보관 기록의 해당 행을 누르거나 같은 스크린샷을 다시 처리하면 새 POST 없이 로그인한 계정의 최근 저장 코드를 읽습니다. 이를 새 발급으로 표시하지 않습니다.

## 검증

합성 코드로 제공된 화면과 같은 제목·전용 표시 영역·문자 묶음·회색 구분자 구조를 로컬 서버에 재현합니다. Qt 브라우저에서 자동 제출 후 앱 표시까지, 중첩된 코드 영역, 하이픈을 포함한 복사 결과, 읽기 전용 입력칸, Unicode 대시, 링크 제외, 기존 저장값 재확인을 검사합니다. 개인 사진과 실제 코드는 배포 소스에 포함하지 않습니다.

실제 SCRMaps 계정으로 발급을 요청하지 않았습니다. Windows 설치/실행과 코드 서명은 별도로 검증해야 합니다.
